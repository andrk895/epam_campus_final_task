## Assessment of the lazy `app.main.app` deviation
I accept it. It is justified, not over-engineered:
- **Correctness:** `uvicorn app.main:app`, `--reload`, `--workers`, gunicorn+uvicorn workers and a Docker `CMD ["uvicorn", "app.main:app", ...]` all get the attribute with `getattr(module, "app")`, which triggers `__getattr__` at startup. Invalid config still fails at startup, not on the first request. I verified this with a real server (exit 1). So T7 (Docker) is not affected.
- **T1.4 fixtures:** the fixtures should call `create_app(settings=test_settings)` anyway, not use the global `app`, because they need test DB and storage settings. The lazy global keeps `app.main` importable during collection without a `.env`, which helps T1.4. The other option (plain `app = create_app()` plus a root conftest that sets `JWT_SECRET` before import) also works. But it depends on import order and makes every test-time import of `app.main` read the developer's real `.env`. Neither option is clearly better, and the chosen one is small (about 10 lines), documented in the module docstring and covered by tests (`test_importing_main_does_not_build_the_app`, `test_uvicorn_entry_point_*`).
- **Disclosure:** the deviation is stated in the module docstring and in progress.md, so it is not silent.
- **Cost:** mypy can no longer catch typos in names imported from `app.main` (see the nit below). This is minor and does not block approval.

## Nits (non-blocking)
- `src/app/main.py:59` — the module-level `__getattr__` makes mypy type every unknown `app.main.<name>` as `FastAPI`, so a typo like `from app.main import craete_app` passes type checking. To keep static checking with the same runtime behaviour, declare `if TYPE_CHECKING: app: FastAPI` and define `__getattr__` only under `if not TYPE_CHECKING:`.
- `src/app/main.py:45` — `dependency_overrides[get_settings]` is used to pin the settings in production too. This works, but in T1.4 a fixture teardown that calls `app.dependency_overrides.clear()` would quietly remove the pin, so `SettingsDep` would fall back to reading the environment. Worth remembering when writing the T1.4 fixtures (re-apply the override or only pop the keys you added).
- `tests/test_main.py:17-40` repeats the env-isolation fixture from `tests/test_config.py`. This is acknowledged and is deferred to T1.4's shared `conftest.py`. Make sure it is actually merged there.
- Record the lazy-entry-point decision in the spec's Design decisions table (or README "Running" notes) so future tasks see it without reading `main.py`.
