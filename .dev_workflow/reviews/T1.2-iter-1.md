## Blocking issues
1. `src/app/models/project.py:141-150`: the `role` column uses `Enum(..., native_enum=False, create_constraint=True)`. With alembic 1.20 / SQLAlchemy 2.1, autogenerate on an empty DB renders the CHECK **twice**: once as `sa.CheckConstraint("role IN (...)", name='project_role')` and again inside `sa.Enum(..., create_constraint=True)`. Both resolve to `ck_project_members_project_role`, so the generated initial migration fails on `alembic upgrade head` (T1.3's Done-when) unless someone hand-edits it. The brief asked whether the schema can be reproduced by autogenerate, so this needs fixing at the source. Expected fix: `Enum(ProjectRole, name="project_role", native_enum=False, create_constraint=False, length=20, validate_strings=True, values_callable=...)` and add `CheckConstraint("role IN ('owner', 'participant')", name="project_role")` to `ProjectMember.__table_args__`. The constraint name stays `ck_project_members_project_role`, so `test_unknown_role_is_rejected_by_the_database` keeps passing. Please also add an assertion to `test_schema_has_the_expected_keys_and_indexes` that `project_members` has exactly one check constraint (`inspector.get_check_constraints("project_members")`), so a duplicate would be caught.
