# Review — T1.4 — iteration 1

## Done-when criteria
- [x] Isolated test DB: a dedicated test database (`TEST_DATABASE_URL`, default `pm_test`) with a uniquely named per-session schema (`tests/database.py` `temporary_schema`). Each xdist worker and each concurrent run gets its own schema, and the schema is dropped at session end.
- [x] Per-test rollback: there is one outer transaction per test on one connection, and sessions use `join_transaction_mode="create_savepoint"`. Commits made in tests and in requests are undone. `test_fixtures.py` checks this with "leave behind, then verify gone" test pairs, and also checks visibility from a separate connection.

- [x] Temp storage dir: `storage_dir` lives under `tmp_path`, is removed after the test, and `tmp_path_retention_policy = "failed"` is set.
- [x] Factories: `create_user` and `create_project` (with the owner membership) are done. `auth_headers` is deferred to T2.4 as the orchestrator agreed, so it does not block this review.
- [x] "Parallel-safe isolation, no data or files left behind": I verified this by running the suite (see below).
- [x] Carry-over: the duplicated env-isolation fixtures from test_config and test_main are now merged into `conftest.py` (`_clean_settings_env` autouse + `isolated_env`).

## Nits (non-blocking)
- pytest-xdist is not a dev dependency, so `-n` only works with `uv run --with pytest-xdist`. Add it to the dev group if parallel runs are meant to be routine (or mention it in the README).
- If a run is aborted (SIGKILL), its `test_<uuid>` schemas stay behind in the test DB. Consider a startup sweep or a README note.
- Every test that uses `client`, even `/health`, now needs PostgreSQL because `app` depends on the DB fixtures. This is acceptable since the README states it, but keep it in mind.
- `auth_headers(user)` still needs to be added in T2.4. Make sure the carry-over notes record it.

## Summary
The fixtures are well designed. Each session gets its own schema in a dedicated test DB, each test runs inside an outer transaction with savepoint-joined sessions so commits in both the app and the tests are rolled back, and the app's real `get_db` path is used without touching `dependency_overrides`. Storage dirs are temporary and cleaned up. The isolation tests are meaningful. The suite passes on both databases, under xdist and in two concurrent runs, and leaves no schemas, tables or files behind. Lint, format and mypy are clean. Refactoring the existing tests onto the shared helpers removed the duplication the carry-over asked about.
