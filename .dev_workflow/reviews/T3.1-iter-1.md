## Nits (non-blocking)
- `src/app/core/errors.py:31,42`: the `# noqa: N818 (name given by the task list)` comments are not accurate. specification.md doesn't name `ProjectNotFound` or `PermissionDenied` (T6.1 only gives the example code `PROJECT_NOT_FOUND`). The names are reasonable; consider rewording the justification.
- `require()` accepts `user: User | int`. A transient `User` with `id=None` would reach `_fits_id_column(None)` and raise a `TypeError`. This can't happen with an authenticated current user, so it's not a real issue.
- The int-range short-circuit is a good defensive choice. The API layer will likely also bound path ids, so this is defence in depth.

## Summary
The access service is small and correct. It is the single place for the role-to-permission policy (read-only `MappingProxyType` of frozensets). It loads the project and the user's membership in one INNER JOIN query, so a non-member and a nonexistent project can't be told apart (same class, code, detail and args), as D7 requires. The domain exceptions don't depend on HTTP and are ready for T6.1. The tests are meaningful: an independent expected matrix, every cell checked on real PostgreSQL, cross-project isolation, a single-query assertion, and out-of-range ids. Tests, lint, format and mypy all pass, apart from the known out-of-scope test_db failure.
